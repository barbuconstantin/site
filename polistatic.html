Polimorfismul Static în C#

Polimorfismul static reprezintă capacitatea unui limbaj de programare de a permite mai multe definiții ale aceluiași nume de metodă sau operator, rezolvate la momentul compilării (compile-time), nu la execuție.

Ce este polimorfismul?

Polimorfismul este unul dintre cei patru piloni fundamentali ai Programării Orientate pe Obiecte (POO), alături de încapsulare, moștenire și abstractizare. Termenul provine din greacă și înseamnă „mai multe forme". În programare, el permite ca un singur identificator să se refere la comportamente diferite în funcție de context.

Tipuri de polimorfism

Polimorfism Static (Compile-time)

Rezolvat la compilare. Include supraîncărcarea metodelor și a operatorilor. Mai rapid — nu are overhead la execuție.

Polimorfism Dinamic (Runtime)

Rezolvat la execuție. Include suprascrierea metodelor (virtual / override). Permite legarea tardivă (late binding).

Supraîncărcarea metodelor (Method Overloading)

Supraîncărcarea metodelor permite definirea mai multor metode cu același nume în aceeași clasă, dar cu parametri diferiți (număr, tip sau ordine). Compilatorul alege metoda potrivită în funcție de argumentele transmise.

Reguli: metodele trebuie să difere prin lista de parametri. Tipul returnat singur nu este suficient pentru a diferenția metodele supraîncărcate.
C# — Method Overloading 
using System;

class Calculator {
    // Varianta 1: doi întregi
    public int Aduna(int a, int b) {
        return a + b;
    }

    // Varianta 2: trei întregi
    public int Aduna(int a, int b, int c) {
        return a + b + c;
    }

    // Varianta 3: două numere reale
    public double Aduna(double a, double b) {
        return a + b;
    }

    // Varianta 4: un șir de caractere și un întreg
    public string Aduna(string text, int numar) {
        return text + numar.ToString();
    }
}

class Program {
    static void Main() {
        Calculator calc = new Calculator();

        Console.WriteLine(calc.Aduna(3, 5));           // → 8
        Console.WriteLine(calc.Aduna(1, 2, 3));        // → 6
        Console.WriteLine(calc.Aduna(2.5, 3.1));       // → 5.6
        Console.WriteLine(calc.Aduna("Număr: ", 42));  // → Număr: 42
    }
}
Rezultat consolă
8 6 5.6 Număr: 42

Supraîncărcarea operatorilor (Operator Overloading)

C# permite redefinirea comportamentului operatorilor standard (+, -, *, == etc.) pentru tipuri definite de utilizator. Acest mecanism este tot o formă de polimorfism static.

C# — Operator Overloading 
using System;

class Vector2D {
    public double X { get; set; }
    public double Y { get; set; }

    public Vector2D(double x, double y) {
        X = x;
        Y = y;
    }

    // Supraîncărcarea operatorului +
    public static Vector2D operator +(Vector2D v1, Vector2D v2) {
        return new Vector2D(v1.X + v2.X, v1.Y + v2.Y);
    }

    // Supraîncărcarea operatorului *
    public static Vector2D operator *(Vector2D v, double scalar) {
        return new Vector2D(v.X * scalar, v.Y * scalar);
    }

    public override string ToString() {
        return $"({X}, {Y})";
    }
}

class Program {
    static void Main() {
        Vector2D v1 = new Vector2D(1, 2);
        Vector2D v2 = new Vector2D(3, 4);

        Vector2D suma = v1 + v2;
        Vector2D produs = v1 * 3;

        Console.WriteLine($"v1 + v2 = {suma}");    // → (4, 6)
        Console.WriteLine($"v1 * 3 = {produs}");    // → (3, 6)
    }
}
Rezultat consolă
v1 + v2 = (4, 6) v1 * 3 = (3, 6)

Avantaje și limite

✓ Avantaje

  • Cod mai clar și mai lizibil — un singur nume de metodă pentru operații similare
  • Fără overhead la execuție — rezolvare la compilare
  • Flexibilitate în proiectarea API-urilor
  • Reducerea numărului de metode cu nume diferite în cod

⚠ Limite

  • Nu permite comportament dinamic (rezolvat la runtime)
  • Tipul de returnare singur nu poate diferenția supraîncărcările
  • Poate crea ambiguitate dacă nu este folosit cu atenție
  • Nu toți operatorii pot fi supraîncărcați în C#
